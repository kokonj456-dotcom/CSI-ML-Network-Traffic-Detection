1. ทำไม XGBoost ต้องสร้างต้นไม้แยกสำหรับ 6 คลาส?

ในปัญหา Multi-class Classification แบบ multi:softprob อัลกอริทึม XGBoost จะสร้างต้นไม้ K=6 ต้นในแต่ละรอบ (Iteration) โดยต้นไม้แต่ละต้นจะมุ่งเป้าไปที่การลด Residual ของคลาสนั้นๆ เมื่อผ่านหลายรอบ ผลรวมคะแนนดิบ z_k ของแต่ละคลาสจะถูกส่งเข้าฟังก์ชัน Softmax เพื่อแปลงเป็นความน่าจะเป็นรวม 100%

2. ทำไมฟีเจอร์ระดับโหนดราก (Root Split) ของแต่ละคลาสจึงต่างกัน?

XGBoost เลือกตัวแปรที่ให้ Information Gain สูงสุดในการแยกคลาสนั้นออกจากคลาสอื่น:

  • Class 2 (Recon): ใช้ state_reset เป็นตัวชี้วัด เพราะการสแกนพอร์ตจะทำให้เซิร์ฟเวอร์ส่ง RST กลับมาเป็นจำนวนมาก
  • Class 5 (Malware C2): ใช้ service_dns เป็นตัวแยก เพราะมัลแวร์ยุคใหม่นิยมใช้ DNS Tunneling ในการสื่อสารหลบหลีกไฟร์วอลล์
  • Class 4 (R2L): ใช้ service_ftp ดักจับการพยายาม Brute Force รหัสผ่าน

3. การันตีได้อย่างไรว่าโมเดลไม่จำข้อสอบ (Overfitting)?

เราใช้ระบบ Early Stopping (Patience = 40) ควบคู่กับ Authentic Validation Set (121,199 โฟลว์จริง 100%) โดยไม่ใช้ข้อมูลสังเคราะห์ SMOTE ในชุดประเมินผลเลยแม้แต่แถวเดียว เมื่อโมเดลเริ่ม Overfit ที่รอบ 203 ระบบจะรอจนครบ 40 รอบแล้วสั่งตัดจบที่รอบ 242 พร้อมทั้ง Rollback คืนค่าน้ำหนักกลับไปที่รอบ 202 ทันที

4. บทบาทของ SMOTENC ใน Model 3 และ Model 4 คืออะไร?

ในทราฟฟิกเครือข่ายจริง คลาสอย่าง Credential Abuse (R2L) หรือ Malware มีสัดส่วนน้อยมาก (Imbalance Ratio สูงถึง 1:1,000) การใช้ SMOTENC เข้ามาช่วยสังเคราะห์ตัวอย่างเฉพาะในชุด Train ทำให้ต้นไม้พยากรณ์สามารถมองเห็น Decision Boundary ของกลุ่มการโจมตีแฝงตัวได้ชัดเจนขึ้น ส่งผลให้ Recall เพิ่มขึ้นจาก 42% เป็นกว่า 88%
